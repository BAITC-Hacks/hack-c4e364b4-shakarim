# Аналитический модуль

Модуль анализирует готовый `node_metrics.csv`. Он не пересчитывает графовые метрики и не строит исходный граф заново. Для каждого `gid` он назначает роль, считает `role_score` и `priority_score`, формирует пояснение `evidence` и сохраняет три CSV-отчёта.

## Запуск

Минимальный запуск использует только подготовленные метрики:

```bash
python3.12 src/pipeline.py --input output/node_metrics.csv --output-dir output
```

Чтобы выполнить кластеризацию Louvain, передайте CSV рёбер:

```bash
python3.12 src/pipeline.py \
  --input output/node_metrics.csv \
  --edges output/edges.csv \
  --output-dir output
```

Без аргумента `--input` pipeline сначала ищет `output/node_metrics.csv`, затем `mock/node_metrics.csv`.

## Входные данные

`node_metrics.csv` содержит одну строку на один `gid`. Используются следующие метрики, рассчитанные до аналитического этапа:

| Колонка | Назначение |
| --- | --- |
| `gid` | Идентификатор узла. Обязателен и должен быть уникален. |
| `depth` | Глубина узла от seed. На глубине 4 отсутствие исходящих операций не доказывает terminal-роль. |
| `is_seed` | Признак исходного seed-узла. |
| `in_amount`, `out_amount` | Входящий и исходящий денежный объём. |
| `in_degree`, `out_degree` | Число входящих и исходящих соседей. |
| `unique_senders`, `unique_receivers` | Число уникальных контрагентов. |
| `in_tx_count`, `out_tx_count` | Число входящих и исходящих транзакций. |
| `pass_ratio`, `pagerank`, `betweenness` | Сохранённые графовые метрики; в текущих правилах ролей напрямую не используются. |

`edges.csv` нужен только для Louvain. В нём необходимы отправитель, получатель и вес: `source`, `target`, `amount`. Поддерживаются также распространённые синонимы: например, `source_gid`, `target_gid`, `amount_kzt`, `sum_kzt`. Каждый `gid` в рёбрах должен присутствовать в `node_metrics.csv`.

## Что делает каждый файл

| Файл | Функция |
| --- | --- |
| `src/pipeline.py` | Читает CSV, проверяет уникальность `gid`, запускает роли, приоритеты, кластеризацию и экспорт. |
| `src/roles.py` | Присваивает одну из шести ролей, считает `role_score`, создаёт короткий `evidence`. |
| `src/priority.py` | Считает `priority_score` от 0 до 1. |
| `src/clustering.py` | Выполняет детерминированный Louvain-style local move на взвешенной неориентированной проекции рёбер. |
| `src/export.py` | Записывает отчёты в фиксированных схемах CSV. |
| `tests/test_analytics.py` | Регрессионные проверки ролей, баллов, границы `depth=4`, кластеризации, экспорта и входных ограничений. |

## Роли

Правила проверяются по порядку. Первое совпавшее правило назначает единственную роль; `role_score` не может заменить результат правила.

1. `peripheral` — нулевой оборот либо не более двух контрагентов и двух транзакций.
2. `terminal` — узел получил деньги и отправил не более 20% входящего объёма. Узел с `depth >= 4` и без исходящих связей исключается из этого правила, потому что данные обрываются на глубине выгрузки.
3. `coordinator` — минимум 5 уникальных отправителей, 5 уникальных получателей и сопоставимые входящий/исходящий обороты: меньший объём составляет минимум 50% большего.
4. `consolidator` — минимум 3 уникальных отправителя, а входящий объём более чем на 20% выше исходящего.
5. `distributor` — минимум 3 уникальных получателя, а исходящий объём более чем на 20% выше входящего.
6. `transit` — есть входящий и исходящий объём; исходящий составляет от 75% до 125% входящего.
7. `peripheral` — fallback для активности, которая не удовлетворяет другим правилам.

`role_score` находится в диапазоне 0–1. Он отражает силу признаков выбранной роли: число контрагентов, баланс потоков и масштаб оборота.

`evidence` содержит конкретные числа: суммы, количество уникальных контрагентов или долю перевода. Его длина ограничена 200 символами.

## Приоритет

`priority_score` находится в диапазоне 0–1 и составляется из ограниченных компонентов:

| Компонент | Максимальный вклад |
| --- | --- |
| Логарифмический денежный оборот | 0.45 |
| Логарифмическая связность | 0.25 |
| Дисбаланс входящего и исходящего потоков | 0.20 |
| `is_seed=true` | 0.10 |

Больший score означает более высокий приоритет ручной проверки. Логарифмические шкалы не дают одному очень крупному обороту полностью определить результат.

## Кластеризация

При передаче `--edges` каждое направленное ребро `source -> target` с весом `amount` добавляется в неориентированную связь между этими узлами. Если существуют переводы в обоих направлениях, их веса суммируются. Louvain использует этот совокупный вес для поиска сообществ.

Направление не теряется из аналитики: входящие и исходящие суммы, степени и транзакционные счётчики остаются в строке `node_metrics.csv` и используются в правилах ролей и приоритета.

Если `--edges` не передан, связи нельзя восстановить из агрегированных метрик. Pipeline честно назначает каждому узлу отдельный `cluster_id`, а `clusters.csv` сообщает об отсутствии исходных связей.

## Выходные файлы

Схемы фиксированы в `src/export.py`.

### `output/nodes_roles.csv`

```text
gid,role,role_score,cluster_id,priority_score,evidence
```

Одна строка на `gid` с результатом аналитики.

### `output/clusters.csv`

```text
cluster_id,n_nodes,n_seed,sum_kzt_internal,top_gids,hypothesis
```

`sum_kzt_internal` — сумма направленных весов рёбер, у которых оба конца попали в один кластер. `top_gids` содержит до пяти узлов с наибольшим `priority_score`.

### `output/top_nodes.csv`

```text
rank,gid,role,priority_score,why
```

Отчёт содержит от 20 до 100 узлов, отсортированных по `priority_score` по убыванию. Если во входе меньше 20 узлов, pipeline завершится с понятной ошибкой и не создаст этот отчёт.

## Тесты

```bash
python3.12 -m unittest discover -s tests -v
```

Тесты не требуют сторонних библиотек. Они проверяют все шесть ролей, диапазоны score, evidence, границу `depth=4`, Louvain-проекцию, фиксированные колонки экспорта и минимальный размер TOP-отчёта.
