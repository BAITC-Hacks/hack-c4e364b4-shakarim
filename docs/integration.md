# Общий pipeline и передача CSV

В общей версии объединены данные и метрики, аналитика и интерфейс. Общий pipeline
создаёт готовые файлы одного запуска и одного датасета в `output/`.
Streamlit читает эти файлы; для внешней папки используется `TRACEFLOW_RESULTS_DIR`.

| Ветка | Ответственность | Передаёт UI |
| --- | --- | --- |
| `dev/data-metrics` | Проверка исходных таблиц, граф и метрики | `node_metrics.csv`, `edges.csv` |
| `analytics` | Роли, приоритет, кластеры и объяснения | `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` |
| `dev/ui` | Отображение, поиск, направленные связи и демо | Сводка по GID; исходные CSV без изменения |

Таблица сохраняет исходное разделение ответственности разработчиков. Общая версия
содержит все компоненты; переключаться между ветками для запуска не требуется.

## Данные для интерфейса

`node_metrics.csv` содержит одну строку на GID. Полный контракт ветки метрик:

```text
gid,depth,is_seed,in_degree,out_degree,in_amount,out_amount,in_tx_count,out_tx_count,
unique_senders,unique_receivers,pass_ratio,pass_through,pagerank,betweenness,truncated_by_depth
```

`pass_ratio = out_amount / in_amount`, если входящая сумма положительна и узел
не seed. `pass_through` — совместимый с ранней версией синоним с теми же значениями.
У seed оба значения пустые: их входящий поток неполон. PageRank взвешен по сумме
переводов; направленная betweenness использует длину ребра `1 / sum_kzt`.

UI присоединяет по строковому GID только `depth`, `is_seed`, `truncated_by_depth`.
Дополнение метаданных из `data/nodes.parquet` допустимо только после проверки
`analysis_context.json` и контрольных сумм исходных файлов и результатов.
Повторяющиеся GID в метаданных вызывают предупреждение; карточка остаётся доступной.
GID сохраняются строками и не преобразуются в JavaScript Number.

Для связей подходят `edges.csv` с `src,dst,sum_kzt,n_tx` или
`source,target,amount`. Приоритет имеет `output/edges.csv`; затем используется
`output/edges.parquet`. Исходный `data/edges.parquet` может дополнять результаты
только при подтверждённом контексте запуска.
Стрелки UI всегда показывают исходное направление. Неориентированная проекция,
которую analytics использует для кластеризации, не заменяет исходные связи.

## Полный запуск из Parquet

Из корня репозитория после установки `requirements.txt` в окружение Python 3.12.10:

```powershell
python run.py
```

`run.py` последовательно запускает расчёт и Streamlit одним интерпретатором.
`--analysis-only` сохраняет CSV без UI, `--ui-only` открывает готовые результаты.
Можно задать `--data`, `--output-dir`, `--port` и `--headless`.

Pipeline проверяет исходные данные, рассчитывает метрики и аналитику, сохраняет
пять CSV: `node_metrics.csv`, `edges.csv`, `nodes_roles.csv`, `clusters.csv`,
`top_nodes.csv`, а также `analysis_context.json`. В интерфейсе нажмите
«Обновить данные» и выберите «Авто: output → mock».

## Повторный запуск аналитики по готовым метрикам

```powershell
python src/pipeline.py --input output/node_metrics.csv --edges output/edges.csv --output-dir output
```

Этот режим использует подготовленные метрики, обновляет три аналитических CSV
и сохраняет метрики и рёбра с каноническими именами колонок в каталоге результатов.
Пять CSV сопровождаются `analysis_context.json` с режимом `metrics`.
Для кластеризации нужен `--edges`; без него каждый GID получает отдельный кластер.
Такой кластер не является выявленным сетевым сообществом. Его `hypothesis`
сообщает об отсутствии связей, а `sum_kzt_internal=0` означает отсутствие
переданных рёбер, а не доказанный нулевой оборот.

Взвешенная неориентированная проекция суммирует веса обоих направлений и
параллельных связей. Louvain выполняется средствами NetworkX с `seed=42`
и `resolution=1`; изоляты получают отдельные сообщества. Переводы самому себе
не участвуют в поиске сообществ, но входят в денежные суммы отчёта.

Без `--edges` pipeline записывает `edges.csv` только с заголовком: старые связи
заменяются, чтобы UI не показал окружение другого набора. При ошибке расчёта
или валидации итоговые CSV не заменяются; публикация начинается после успешной
подготовки всех файлов во временном каталоге.

## Передача результатов интерфейсу

Передавайте пять CSV и `analysis_context.json` одного запуска в `output/`
либо задайте отдельную папку:

```powershell
$env:TRACEFLOW_RESULTS_DIR = "C:\path\to\ready-output"
python -m streamlit run ui/app.py
```

Контекст связывает режим расчёта, абсолютный путь `data_dir`, SHA-256 трёх Parquet
(`source_sha256`) и пяти CSV (`output_sha256`), версия схемы — 1. История
транзакций и дополнение метаданных из Parquet доступны в режиме результатов только
при `mode=parquet`, совпадающем пути `TRACEFLOW_DATA_DIR` и всех контрольных суммах.
После изменения исходников, результатов или пути повторите полный расчёт.

При расчёте из метрик, отсутствии или несовпадении контекста UI показывает готовую
аналитику и связи из CSV, но не подключает исходные Parquet другого запуска.
Дневная история тогда недоступна; пояснение видно в интерфейсе. Режим «Исходные
данные» отдельно показывает Parquet без аналитических ролей и приоритетов.

## Проверка общего контракта

```powershell
python -m unittest discover -s tests -v
```

Проверки включают полноту GID, соответствие сумм и количества транзакций,
метрики, роли, экспорт и открытие результатов в Streamlit. Для приложенного
датасета ожидаются 2 248 узлов, 3 119 направленных связей и 4 840 транзакций.
Обе оценки используют диапазон 0–1, `evidence` ограничен 200 символами.
У seed `pass_ratio` и `pass_through` отсутствуют, узлы `depth >= 4` без исходящих связей
не получают роль `terminal` по отсутствию исходящего потока.

Сгенерированные CSV и JSON-контекст оставлены локально в `output/` и исключены из Git.
Синтетический `mock/` версионируется и обеспечивает независимый запуск UI.
